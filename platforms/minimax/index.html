先看是否适合自己

MiniMax Token Plan 是以 MiniMax 模型为主的个人订阅，当前收录新 Plus、新 Max、新 Ultra 三档。现有平台资料把它定位为额度较高、可随时购买、适合日常编程助手与 Agent 任务的服务。

  • 可以优先考虑：日常需要持续使用编程助手，或会运行 Agent、酒馆、Subagent，希望把预算固定在月度订阅内。
  • 先比较再决定：希望在同一个订阅中频繁切换多家模型，或主要为自建应用购买通用 API 服务。
  • 购买前先确认：所用客户端是否支持 MiniMax Token Plan 的接入方式，常用模型是否在当前套餐中，以及自己的任务会先触及五小时还是周窗口。

本页沿用本站现有平台、套餐、模型和 PlanModel 记录。介绍更新时间与数据记录日期分开显示；实测用量是特定负载下的参考，不是官方承诺的固定 Token 包。

接入工具与使用边界

MiniMax Token Plan 可用于官方 MiniMax Code，也可以按官方说明获取对应的 Token Plan Key，接入支持的 OpenAI 兼容工具。实际配置时要区分 Token Plan 端点、API 端点和普通 API 余额，不能因为客户端接受 API Key 就默认请求会消耗订阅额度。

建议按以下顺序检查：

  1. 确认账号、套餐和密钥属于同一 MiniMax 产品线。
  2. 按官方当前说明配置端点、模型 ID 和鉴权方式。
  3. 先运行一个小任务，检查用量是否记入预期套餐。
  4. 确认正常后，再放大到长上下文、多模态和连续 Agent 任务。

如果是为自己的网站、应用或其他服务选购模型，需要另行确认 API 的计费方式与服务条款；不要把个人 Token Plan 订阅当成所有调用场景的通用余额。

MiniMax 选购时容易混淆的地方

M3、M2.7 与 M2.5 的用量不能混看

三款模型都在现有套餐支持关系中，但当前只有 M3 有可展示的实测用量。M2.7 和 M2.5 的“支持”不等于已经有可独立换算的额度，不能用 M3 的 Token 数字替代它们。

实测参考不等于官方额度

本站的 M3 数值来自个人实测，并按现有套餐比例推导 Max 与 Ultra。它用于统一条件下的比较，不能覆盖所有缓存命中率、输出长度、上下文规模和多模态任务；购买前应以官方用量页为准。

订阅与 API 产品线要分开

MiniMax 同时提供 Token Plan 和 API 服务。若目标是程序化调用、自建应用或按 API 价格控制成本，应单独核对 API 产品的模型、价格和限流规则；不要只看 Token Plan 的月费。
