先看是否适合自己

MiniMax 当前面向新用户提供 M Plan Go、Explore、Build，包含 MiniMax Code 和可接入其他编程工具的订阅 API Key。MiniMax Code Free 可以有限使用新型号，但没有订阅 API Key。

适合主要使用 MiniMax 模型、希望按月管理预算的个人用户。若经常切换多家模型，或需要为自建应用购买通用 API，应另外比较对应产品。

截至 2026-10-25，所有订阅用户在 MiniMax Code 内使用 M3.1 Flash 不限量。该活动不包含 Code Free，也未承诺外部工具 API 不限量；未公布具体截止时刻。

常规情况下，文本等非视频模型受五小时和七天窗口控制，两者都需有剩余额度。各模态共享套餐额度；视频只受周窗口控制。未用完的额度不结转，五小时刷新不会恢复本周已用额度。

M3.1 Flash 的官方固定 Token 配额尚未公开。这里的用量是社区样本推算，按输入缓存命中率 95%、输出占全部 Token 的 0.5%计算；Go 五小时约 4,444 万 Token，Explore、Build 分别按 Go 的 3 倍、12 倍估算。周参考量按五小时的 10 倍、月参考量按四周换算，不代表另有独立月额度池。

估算采用新增输入、输出、缓存读取按 1、4、0.2 加权消耗的假设，Go 五小时约 1,150 万加权 Token。这些系数不是官方公布的订阅扣减规则，也不是 M3.1 Flash 的按量 API 报价。缓存读取计入参考 Token 总数；思考输出更多、缓存命中更低或混用其他模态时，实际总量可能明显减少。旧 M3 实验仍只作历史资料，没有直接移植为新型号实测额度。

接入工具与使用边界

订阅 M Plan 后可直接登录 MiniMax Code 使用；接入 Claude Code、Codex、Cursor、OpenCode 等工具时使用订阅 Key。它与按量 API Key 不通用。

订阅额度耗尽后，如有积分包则继续消耗积分包；不会自动扣开放平台账户余额。自建应用和生产服务应核对按量 API 的适用规则。

MiniMax 选购时容易混淆的地方

旧 Token Plan 续费与新 M Plan 订购有不同权益；型号替换也不等于可以把旧测量当成新型号的保证。长期预算应看续费价、窗口和自己真实的任务消耗。
