先看是否适合自己

OpenCode Go 提供多模型订阅，适合经常根据任务切换模型的编程用户。选择它之前，先列出自己最常用的两三种模型，再查看这些模型在套餐中的限制。

  • 可以优先考虑：想在同一个接入方式下尝试不同模型，并希望先控制订阅支出。
  • 先比较再决定：长期只使用一个模型，或需要持续高强度调用而不愿关注各模型的用量窗口。
  • 购买前先确认：常用模型的额度、客户端兼容情况，以及额度耗尽后的行为。

同一个套餐包含很多模型，不意味着每个模型都有相同的可用量，也不意味着额度可以无条件相加。

OpenCode、Go 与 Zen 是什么关系

OpenCode 是编程工具，Go 是可选的模型订阅。使用 OpenCode 不等于必须购买 Go；配置其他服务商时，费用仍遵循对应服务商的规则。

Go 的订阅额度与 Zen 余额需要分开理解。Go 文档介绍了超出订阅限制后使用余额的设置。若希望控制总支出，订阅前应检查自己的余额回退选项，避免把月费误当作所有情况下的总费用上限。

客户端接入要点

在 OpenCode 中，按官方文档添加 Go 提供商并选择模型即可。接入其他编程工具时，应先查看 Go 文档中的客户端支持说明，不要只凭“兼容某种 API 协议”判断可以直接使用。

模型可能采用不同协议和端点，客户端也需要正确保留会话信息。若出现同一个密钥在不同工具中表现不一致的情况，先核对提供商、模型 ID、端点和客户端版本，再判断是否为额度或服务问题。

具体配置以Go 接入文档为准。

怎么安排自己的模型组合

从真实任务出发

先确定一个日常模型，用来处理小改动、解释代码和常规实现；再选择另一个模型处理难题或复核重要修改。是否值得切换，应以任务结果和消耗判断，而不只看额度数字。

不为临时加成做长期预算

新模型可能有阶段性额度加成。可以用活动期体验模型，但长期预算仍应参考常规规则，并确认活动结束后的可用量。最新日期和条件见官方活动说明。

控制超额开支

检查是否启用了订阅耗尽后使用余额的功能。对持续自动运行的任务，除了限制轮次和执行范围，也要观察实际账单。这样才能分清月费、订阅内使用和额外消费。
