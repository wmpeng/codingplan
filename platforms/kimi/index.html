适合什么人

如果日常主要使用 Kimi 写代码，希望在官方客户端与其他编程工具之间切换，可以考虑 Kimi Code。它随会员提供，与其他会员功能共享额度；仅购买 Go 不包含编程额度。

需要为应用提供通用模型服务时，应另行比较开放平台 API，不能把个人会员当作通用 API 余额。

K3.1 Pro 从 Plus 起可用；Plus 最高 256K 上下文，Pro 及以上支持最高 1M，并可使用高速版。高速版能力相同，输出约快 2–3 倍，消耗约为标准版两倍；它不是额外一份额度。

旧套餐的 Moderato 也可使用最高256K的 K3.1 Pro；Allegretto、Allegro 支持最高1M及高速版，额度仍按各自旧套餐规则使用。

K3.1 Pro 支持图片和视频输入，必须开启思考，默认 high。旧 K3 的 k3 与 k3-256k 也有不同的上下文、模态和扣减规则，不能只看名称中是否出现 256K。

新旧套餐的额度差异

新套餐没有独立周限额，仍受五小时滚动窗口及共享月总额约束。所有客户端、设备和 API Key 共用额度；月总额耗尽后，等待五小时窗口恢复也不会补回月额度。

旧 Andante、Moderato、Allegretto、Allegro 供原订阅用户继续使用和续订，仍有周窗口，不能与新套餐套用同一套规则。升级前比较原有权益及新档权限。订阅耗尽后若开启加油包，会继续扣加油包余额，应同时检查月消费上限。

K3.1 Pro 的新套餐参考量暂按 K3 的 85% 扣额估算，同样的缓存率和输出占比下，约可用 K3 的 1.18 倍 Token。这个相对系数来自老套餐社区样本；新套餐的绝对池、跨档倍率及该系数的适用性均未逐档实测，不能视为官方配额或官方加量承诺。高速版参考量为标准版的一半。

老 Allegretto、Allegro 的 K3.1 Pro 采用各自的社区拟合系数，五小时／周窗口按 1∶5；月度共享池未量化，月参考保持待确认。老 Moderato 也保持待确认。社区在 10 月 24–25 日观察到扣额系数变化，实际用量以账号当前读数为准；不能把首发消耗、旧 K3 历史参考和不同缓存率的总 Token 直接比较。

接入与常见问题

官方客户端使用会员账号登录；第三方工具在 Kimi Code 控制台创建 API Key，再按官方接入文档配置协议和模型 ID。Code Key 与开放平台的按量计费需要分开管理。

国内 OpenAI 格式端点为 https://api.kimi.com/coding/v1，Anthropic 格式为 https://api.kimi.com/coding/。K3.1 Pro 的模型 ID 为 k3.1-pro，高速版为 k3.1-pro-highspeed；使用前确认工具能保留思考设置和所需协议。

切换模型建议新建会话，避免旧缓存失效和上下文混用。权限错误先查订阅档位；关闭 K3.1 Pro 的思考或超出上下文上限，也可能导致请求失败。
